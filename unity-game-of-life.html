Conway's Game of Life

A small Unity coding project that starts with one Gemini prompt, then follows up with a camera fix so the simulation fills the game view.

Chapter 1: Create the simulation script

The first prompt was direct: make John Conway's Game of Life in Unity. Gemini returned a C# script that creates a texture, treats each pixel as a cell, randomizes the starting grid, and updates the board with the Game of Life rules.

Source conversation: Google AI Mode share link

Step 1: Set up the Unity object

In a 2D Unity project, create an empty GameObject named Simulation. Then create a C# script named GameOfLife and attach it to that object.

Step 2: Add the first script

 </>  C#
using UnityEngine;

public class GameOfLife : MonoBehaviour
{
    public int width = 100;
    public int height = 100;
    public float timeStep = 0.1f;

    private Texture2D texture;
    private Color[] currentGrid;
    private Color[] nextGrid;
    private float timer;

    void Start()
    {
        texture = new Texture2D(width, height)
        {
            filterMode = FilterMode.Point
        };

        Sprite sprite = Sprite.Create(texture, new Rect(0, 0, width, height), new Vector2(0.5f, 0.5f));
        GameObject go = new GameObject("GridRenderer");
        go.AddComponent<SpriteRenderer>().sprite = sprite;

        currentGrid = new Color[width * height];
        nextGrid = new Color[width * height];

        RandomizeGrid();
    }

    void Update()
    {
        timer += Time.deltaTime;

        if (timer >= timeStep)
        {
            timer = 0f;
            CalculateNextGeneration();
        }
    }

    void RandomizeGrid()
    {
        for (int x = 0; x < width; x++)
        {
            for (int y = 0; y < height; y++)
            {
                bool isAlive = Random.value > 0.5f;
                currentGrid[y * width + x] = isAlive ? Color.white : Color.black;
            }
        }

        texture.SetPixels(currentGrid);
        texture.Apply();
    }

    void CalculateNextGeneration()
    {
        for (int x = 0; x < width; x++)
        {
            for (int y = 0; y < height; y++)
            {
                int aliveNeighbors = CountAliveNeighbors(x, y);
                int index = y * width + x;
                bool isAlive = currentGrid[index] == Color.white;

                if (isAlive)
                {
                    if (aliveNeighbors < 2 || aliveNeighbors > 3)
                        nextGrid[index] = Color.black;
                    else
                        nextGrid[index] = Color.white;
                }
                else
                {
                    if (aliveNeighbors == 3)
                        nextGrid[index] = Color.white;
                    else
                        nextGrid[index] = Color.black;
                }
            }
        }

        Color[] temp = currentGrid;
        currentGrid = nextGrid;
        nextGrid = temp;

        texture.SetPixels(currentGrid);
        texture.Apply();
    }

    int CountAliveNeighbors(int x, int y)
    {
        int count = 0;

        for (int i = -1; i <= 1; i++)
        {
            for (int j = -1; j <= 1; j++)
            {
                if (i == 0 && j == 0) continue;

                int nx = x + i;
                int ny = y + j;

                if (nx < 0) nx = width - 1;
                if (nx >= width) nx = 0;
                if (ny < 0) ny = height - 1;
                if (ny >= height) ny = 0;

                int index = ny * width + nx;
                if (currentGrid[index] == Color.white)
                {
                    count++;
                }
            }
        }

        return count;
    }
}

Step 3: Run the scene

Press Play in Unity. The simulation should create a GridRenderer object and show a randomized black-and-white cellular field that evolves over time.

Chapter 2: Fit the camera to the grid

The first version worked, but the projected play area appeared too small. The second prompt asked how to sync the play area to the camera. The fix is to create the sprite at one pixel per Unity unit and then size the orthographic camera from the grid dimensions.

Step 1: See the camera problem

The simulation worked, but the grid rendered as a tiny square inside a much larger camera view. That made it hard to see the cells clearly, so the next change fits the camera to the generated sprite.

Step 2: Replace the Start method

Step 3: Add FitCameraToGrid

 </>  C#
void FitCameraToGrid()
{
    Camera mainCam = Camera.main;
    if (mainCam == null) return;

    mainCam.transform.position = new Vector3(0, 0, -10);
    mainCam.orthographic = true;

    float screenRatio = (float)Screen.width / Screen.height;
    float gridRatio = (float)width / height;

    if (screenRatio >= gridRatio)
    {
        mainCam.orthographicSize = height / 2f;
    }
    else
    {
        mainCam.orthographicSize = (width / 2f) / screenRatio;
    }
}

The important new line is FitCameraToGrid();. It is now enabled as the last line of Start(), after the grid is created and randomized, so the camera can resize itself when the scene begins.

Step 4: Verify the camera fix

Run the scene again and check that:

  • The Main Camera is orthographic.
  • The camera is centered at (0, 0, -10).
  • The simulation fills the game view instead of sitting as a tiny square.
  • The cell edges stay crisp because the texture uses point filtering.

Chapter 3: Break down the GameOfLife script

The script works because Unity gives us two main entry points: Start() runs once when the scene begins, and Update() runs every frame. The helper methods do the Game of Life work: RandomizeGrid() creates the first board, CalculateNextGeneration() applies the rules, and CountAliveNeighbors() looks around each cell.

Step 1: Store the simulation state

The script stores the grid as one long array instead of a two-dimensional array. A cell at x and y becomes y * width + x. That formula turns a grid position into an array index. 

 </>  C#
public int width = 100;
public int height = 100;
public float timeStep = 0.1f;

private Texture2D texture;
private Color[] currentGrid;
private Color[] nextGrid;
private float timer;

currentGrid is the board being displayed right now. nextGrid is where the next generation is prepared. Keeping them separate matters because every cell must be calculated from the same old board state.

Step 2: Use Start to build the board once

Start() sets up the texture, creates a sprite to display it, creates the two grid arrays, fills the first grid randomly, and then fits the camera. 

 </>  C#
void Start()
{
    // Create a texture where each pixel can represent one cell.
    texture = new Texture2D(width, height)
    {
        filterMode = FilterMode.Point
    };

    // Turn the texture into a visible sprite in the Unity scene.
    Sprite sprite = Sprite.Create(
        texture,
        new Rect(0, 0, width, height),
        new Vector2(0.5f, 0.5f),
        1f
    );

    GameObject go = new GameObject("GridRenderer");
    go.AddComponent<SpriteRenderer>().sprite = sprite;

    // One array holds the current generation.
    // The other array is used to build the next generation.
    currentGrid = new Color[width * height];
    nextGrid = new Color[width * height];

    RandomizeGrid();
    FitCameraToGrid();
}

Step 3: Use Update as the simulation clock

Update() runs every frame, but the simulation should not necessarily advance every frame. The timer lets the script wait until timeStep seconds have passed before calculating the next generation. 

 </>  C#
void Update()
{
    // Add the time since the previous frame.
    timer += Time.deltaTime;

    // Only advance the simulation when enough time has passed.
    if (timer >= timeStep)
    {
        timer = 0f;
        CalculateNextGeneration();
    }
}

Step 4: RandomizeGrid creates generation zero

RandomizeGrid() visits every grid coordinate and randomly marks the cell alive or dead. Alive cells are white. Dead cells are black. After the array is filled, the colors are pushed into the texture so Unity can draw them. 

 </>  C#
void RandomizeGrid()
{
    for (int x = 0; x < width; x++)
    {
        for (int y = 0; y < height; y++)
        {
            // Convert x/y into the matching position in the flat array.
            int index = y * width + x;

            // Random.value returns a float from 0 to 1.
            // Greater than 0.5 gives a rough 50/50 starting board.
            bool isAlive = Random.value > 0.5f;
            currentGrid[index] = isAlive ? Color.white : Color.black;
        }
    }

    texture.SetPixels(currentGrid);
    texture.Apply();
}

Step 5: CalculateNextGeneration applies the rules

CalculateNextGeneration() loops over every cell, counts its living neighbors, and writes the cell's future state into nextGrid. The key detail is that it reads from currentGrid while writing to nextGrid. 

 </>  C#
void CalculateNextGeneration()
{
    for (int x = 0; x < width; x++)
    {
        for (int y = 0; y < height; y++)
        {
            int aliveNeighbors = CountAliveNeighbors(x, y);
            int index = y * width + x;
            bool isAlive = currentGrid[index] == Color.white;

            // Living cells survive with 2 or 3 living neighbors.
            if (isAlive)
            {
                nextGrid[index] = aliveNeighbors < 2 || aliveNeighbors > 3
                    ? Color.black
                    : Color.white;
            }
            // Dead cells become alive with exactly 3 living neighbors.
            else
            {
                nextGrid[index] = aliveNeighbors == 3
                    ? Color.white
                    : Color.black;
            }
        }
    }

    // Swap the arrays instead of copying every cell back manually.
    Color[] temp = currentGrid;
    currentGrid = nextGrid;
    nextGrid = temp;

    texture.SetPixels(currentGrid);
    texture.Apply();
}

The swap is a small but important trick. After the next board is ready, currentGrid and nextGrid trade places. That makes the newly calculated board become the visible current board.

Step 6: CountAliveNeighbors checks the eight surrounding cells

CountAliveNeighbors() looks at a 3 by 3 area around the current cell. It skips the center cell because a cell is not its own neighbor. The edge wrapping makes the grid behave like it loops around at the borders. 

 </>  C#
int CountAliveNeighbors(int x, int y)
{
    int count = 0;

    for (int i = -1; i <= 1; i++)
    {
        for (int j = -1; j <= 1; j++)
        {
            // Skip the cell in the middle.
            if (i == 0 && j == 0) continue;

            int nx = x + i;
            int ny = y + j;

            // Wrap around the grid edges.
            if (nx < 0) nx = width - 1;
            if (nx >= width) nx = 0;
            if (ny < 0) ny = height - 1;
            if (ny >= height) ny = 0;

            int index = ny * width + nx;
            if (currentGrid[index] == Color.white)
            {
                count++;
            }
        }
    }

    return count;
}

Step 7: Read the whole loop as a story

The whole script can be read in this order:

  1. Start() creates the visual grid and calls RandomizeGrid().
  2. RandomizeGrid() creates the first random generation.
  3. Update() waits until timeStep seconds pass.
  4. Update() calls CalculateNextGeneration().
  5. CalculateNextGeneration() asks CountAliveNeighbors() about every cell.
  6. The next grid becomes the current grid and the texture is redrawn.

Chapter 4: Add grid lines and cell colors

The first version used the same data for simulation and rendering: white pixels meant alive, and black pixels meant dead. To make the board easier to read, we split those concerns apart. The simulation now stores alive/dead state as booleans, and a new render method draws that state with larger cells, black grid lines, gray dead cells, and green live cells.

Step 1: Add visual settings

These public fields make the look of the board adjustable in the Unity Inspector. cellSize controls how many texture pixels each logical cell uses, and gridLineSize controls the black spacing between cells. 

 </>  C#
public int cellSize = 8;
public int gridLineSize = 1;
public Color aliveColor = new Color(0.2f, 0.9f, 0.25f);
public Color deadColor = new Color(0.32f, 0.34f, 0.36f);
public Color gridColor = Color.black;

Step 2: Store cells as true or false

The Game of Life rules only need to know whether a cell is alive. Instead of storing Color.white and Color.black in the grid arrays, the script now stores true for alive and false for dead. 

 </>  C#
private bool[] currentGrid;
private bool[] nextGrid;

This makes the simulation logic independent from the visual style. We can change the colors later without changing the Game of Life rules.

Step 3: Build a larger render texture

A one-pixel cell has no room for a visible border. The new texture is bigger than the logical grid because every cell gets its own block of pixels, plus grid-line pixels around it. 

 </>  C#
cellSize = Mathf.Max(1, cellSize);
gridLineSize = Mathf.Max(0, gridLineSize);
pixelsPerUnit = cellSize + gridLineSize;
renderWidth = width * cellSize + (width + 1) * gridLineSize;
renderHeight = height * cellSize + (height + 1) * gridLineSize;

texture = new Texture2D(renderWidth, renderHeight)
{
    filterMode = FilterMode.Point
};

Step 4: Randomize the state, then render it

RandomizeGrid() now fills the boolean state array and then calls RenderGrid(). It no longer writes colors directly to the texture. 

 </>  C#
void RandomizeGrid()
{
    for (int x = 0; x < width; x++)
    {
        for (int y = 0; y < height; y++)
        {
            bool isAlive = Random.value > 0.5f;
            currentGrid[y * width + x] = isAlive;
        }
    }

    RenderGrid();
}

Step 5: Draw the styled grid in RenderGrid

RenderGrid() starts by filling the whole texture with gridColor. Then it draws each cell as a colored rectangle. Because the grid-line pixels are left untouched, they stay black. 

 </>  C#
void RenderGrid()
{
    Color[] pixels = new Color[renderWidth * renderHeight];

    for (int i = 0; i < pixels.Length; i++)
    {
        pixels[i] = gridColor;
    }

    for (int x = 0; x < width; x++)
    {
        for (int y = 0; y < height; y++)
        {
            int gridIndex = y * width + x;
            Color cellColor = currentGrid[gridIndex] ? aliveColor : deadColor;

            int startX = gridLineSize + x * (cellSize + gridLineSize);
            int startY = gridLineSize + y * (cellSize + gridLineSize);

            for (int px = 0; px < cellSize; px++)
            {
                for (int py = 0; py < cellSize; py++)
                {
                    int textureIndex = (startY + py) * renderWidth + (startX + px);
                    pixels[textureIndex] = cellColor;
                }
            }
        }
    }

    texture.SetPixels(pixels);
    texture.Apply();
}

Step 6: Keep the rules the same

The Game of Life rules did not change. The only difference is that the script now writes true or false into nextGrid instead of writing colors. 

 </>  C#
bool isAlive = currentGrid[index];

if (isAlive)
{
    nextGrid[index] = aliveNeighbors < 2 || aliveNeighbors > 3
        ? false
        : true;
}
else
{
    nextGrid[index] = aliveNeighbors == 3;
}

Step 7: Fit the camera to the rendered texture

Since the rendered texture is now larger than the logical grid, the camera uses the rendered world size instead of just width and height. 

 </>  C#
float worldWidth = renderWidth / pixelsPerUnit;
float worldHeight = renderHeight / pixelsPerUnit;
float gridRatio = worldWidth / worldHeight;

if (screenRatio >= gridRatio)
{
    mainCam.orthographicSize = worldHeight / 2f;
}
else
{
    mainCam.orthographicSize = (worldWidth / 2f) / screenRatio;
}

Step 8: Check the styled grid in Unity

After the render pass is separated from the simulation rules, the board is much easier to read: live cells are green, dead cells are gray, and the black grid lines show the boundaries between cells.
