Unity by Code

Asteroids Arena

A first pass at a code-first Unity arcade prototype: one manager script builds the camera, arena, ship, bullets, asteroids, materials, collisions, waves, scoring, lives, and restart flow from simple runtime objects.

Chapter 1: Build the first playable arena

The goal was to explore what Unity can do when most of the game is generated from code instead of imported art assets. The previous scene already held a Conway's Game of Life prototype, so this pass preserved that work and created a separate scene named AsteroidsArena.

Step 1: Create a separate scene

The new scene keeps this arcade experiment isolated from the Game of Life scene. Unity's 2D template supplied the starting camera, and the new script configures that camera at runtime. 

 </>  Unity setup
Scene: Assets/Scenes/AsteroidsArena.unity
GameObject: Asteroids Arena Game
Component: AsteroidsArenaGame
Camera: Main Camera

Step 2: Put the game loop in one script

The first version lives in AsteroidsArenaGame.cs. It is intentionally compact for a prototype: the manager owns the arena state, creates the player ship, creates procedural rocks and bullets, checks collisions, draws the immediate-mode HUD, and advances waves.

A snapshot of the script is stored with this devlog at asteroids-arena-game/AsteroidsArenaGame.cs.

Step 3: Generate placeholder art from code

The ship is a small triangle-like mesh, the thrust flame is another triangle, bullets are tiny discs, and asteroids are irregular polygon meshes. The only primitive GameObjects are the four thin cube boundaries that draw the arena frame.

Step 4: Smoke test in Play Mode

The first Play Mode smoke test exposed two useful issues: the generated flat meshes were invisible because the triangle winding faced away from the camera, and the tall Game view needed a wider orthographic fit. The fix flipped the generated triangle order and sized the camera from both arena height and arena width.

Chapter 2: How the main game script is organized

AsteroidsArenaGame is a Unity MonoBehaviour. Public fields expose tuning values in the Inspector, private fields hold runtime state, and three runtime lists track rocks and bullets while the game is running.

Step 1: Tune the arena, ship, and weapons

The top of the script defines the size of the arena, the starting lives, how many rocks appear in the first wave, the ship acceleration and drag, and the bullet speed, lifetime, and fire cooldown. These values are public so the prototype can be tuned from Unity without changing code. 

 </>  C#
[Header("Arena")]
public float arenaHalfWidth = 12f;
public float arenaHalfHeight = 7f;
public int startingLives = 3;
public int startingRocks = 7;

[Header("Ship")]
public float shipAcceleration = 16f;
public float shipTurnSpeed = 220f;
public float shipMaxSpeed = 8f;
public float shipDrag = 0.985f;

[Header("Weapons")]
public float bulletSpeed = 13f;
public float bulletLifetime = 1.25f;
public float fireCooldown = 0.16f;

Step 2: Store runtime state

The script keeps references to generated materials, the ship transform, the thrust flame transform, score, lives, wave number, shield timing, and the current lists of bullets and rocks. This keeps the first pass direct: one object owns the entire prototype loop.

Chapter 3: Method-by-method breakdown

This chapter walks through the first pass one method at a time. The script has three layers: setup methods, gameplay methods, and tiny helper behaviours for moving rocks and bullets.

Start

Start() runs once when Play Mode begins. It seeds Unity's random number generator, grabs the main camera, configures the camera, creates all runtime materials, draws the arena frame, creates the player ship, and then calls ResetGame() to begin wave one. 

 </>  C#
void Start()
{
    Random.InitState(System.DateTime.Now.Millisecond);
    mainCamera = Camera.main;
    ConfigureCamera();
    CreateMaterials();
    CreateArenaFrame();
    CreateShip();
    ResetGame();
}

Update

Update() is the frame-by-frame game loop. If the game is over, it only watches for restart input. Otherwise it reads player input, cleans up expired bullets and destroyed rocks, checks bullet impacts, checks ship collisions, and starts the next wave when all rocks are gone.

ResetGame

ResetGame() clears old runtime objects, resets score, lives, wave number, and game-over state, respawns the ship at the center, and starts the first wave. This same method is used both for the first run and for restart after game over.

ConfigureCamera

ConfigureCamera() makes sure there is a camera, places it at (0, 0, -10), switches it to orthographic projection, and sets the background color. The orthographic size uses both arena height and arena width so the frame stays visible even when the Game view is tall. 

 </>  C#
float paddedHeight = arenaHalfHeight + 1.2f;
float paddedWidthAsHeight = (arenaHalfWidth + 1.2f) / Mathf.Max(0.1f, mainCamera.aspect);
mainCamera.orthographicSize = Mathf.Max(paddedHeight, paddedWidthAsHeight);

CreateMaterials

CreateMaterials() builds all colors at runtime: cyan for the ship, amber for the flame, mint for bullets, blue for the arena frame, and a small palette for the rocks. No material assets are required for this first prototype.

MakeMaterial

MakeMaterial() is a compatibility helper. It tries to use the URP unlit shader first, then falls back to older unlit or sprite shaders. It also checks both _BaseColor and _Color so the same method works across common Unity render setups.

CreateArenaFrame

CreateArenaFrame() creates a parent object named Procedural Arena Frame and then adds four boundary lines: top, bottom, left, and right. These boundaries are visual, not physical; gameplay wrapping is handled in code.

CreateLine

CreateLine() creates one thin cube, positions it, scales it, applies the arena material, and removes its collider. Removing the collider is deliberate because collisions use simple distance checks instead of Unity physics in this version.

CreateShip

CreateShip() creates the player GameObject, assigns a generated ship mesh, applies the ship material, and stores the transform. It also creates a child thrust flame mesh and keeps it disabled until the player presses thrust.

CreateShipMesh

CreateShipMesh() returns a small four-vertex mesh shaped like an arcade ship. The triangle order faces the camera, which mattered after the first smoke test showed the flat meshes were being culled.

CreateFlameMesh

CreateFlameMesh() returns a simple triangle used as the ship's exhaust flame. During movement, HandleShipInput() pulses this mesh by scaling it on the local Y axis.

CreateRockMesh

CreateRockMesh() is the most procedural part of the first pass. It picks 9 to 14 points, places them around a circle, and gives each point a random radius wobble. The result is an irregular polygon that reads as an asteroid without importing an image or model. 

 </>  C#
float angle = (Mathf.PI * 2f * i) / points;
float wobble = Random.Range(0.68f, 1.15f);
vertices[i + 1] = new Vector3(
    Mathf.Cos(angle) * radius * wobble,
    Mathf.Sin(angle) * radius * wobble,
    0f
);

CreateDiscMesh

CreateDiscMesh() creates a small filled circle from triangle fan geometry. It is used for bullets, so each shot is also generated from code rather than loaded from an asset.

HandleShipInput

HandleShipInput() reads keyboard and mouse input. Left and right rotate the ship, up applies acceleration in the ship's facing direction, drag softens the velocity, and the ship wraps around the arena edges. The same method toggles and pulses the flame, then calls FireBullet() when the cooldown allows another shot.

FireBullet

FireBullet() creates a bullet GameObject at the nose of the ship, assigns a generated disc mesh, and gives it an initial velocity made from bullet speed plus the ship's current velocity. That makes shots feel connected to the ship's motion.

SpawnWave

SpawnWave() increments the wave number and creates a batch of rocks. Each wave adds one more rock than the last, so the first prototype already has a simple difficulty curve.

RandomEdgePosition

RandomEdgePosition() chooses either a horizontal or vertical arena edge, then returns a random point along that edge. New rocks enter from the perimeter instead of spawning directly on top of the player.

SpawnRock

SpawnRock() clamps the rock size, converts size into a radius, creates a GameObject, assigns a procedural rock mesh and random material, then attaches an AsteroidsRock behaviour to move and wrap it.

UpdateBullets

UpdateBullets() removes null references from the bullet list. Bullets destroy themselves when their lifetime ends, so the manager only needs to keep the list tidy before collision checks.

UpdateRocks

UpdateRocks() does the same cleanup for rocks. Destroyed rocks leave null list entries, and this method removes those entries before the next frame's game logic continues.

CheckBulletHits

CheckBulletHits() compares every bullet against every rock using distance checks. If the bullet is close enough to a rock's radius, the bullet is destroyed and BreakRock() handles the asteroid split or removal.

CheckShipHits

CheckShipHits() skips collision checks while respawn shields are active. After shields expire, it checks the ship against each rock by distance. A hit calls LoseLife().

BreakRock

BreakRock() removes the hit rock, awards score based on size, and splits medium or large rocks into two smaller rocks. The split rocks inherit a little of the parent velocity plus a new random impulse.

DestroyBullet

DestroyBullet() removes a bullet from the manager list and destroys its GameObject. It centralizes bullet cleanup so hit detection does not duplicate that logic.

LoseLife

LoseLife() subtracts one life. If no lives remain, the ship is hidden and the game enters the game-over state. Otherwise, the ship is respawned at the center with temporary shields.

RespawnShip

RespawnShip() reactivates the ship, resets its position, rotation, and velocity, delays firing very briefly, and sets the invulnerability timer. The HUD shows SHIELDS ONLINE while this timer is active.

ClearRuntimeObjects

ClearRuntimeObjects() destroys all generated bullets and rocks and clears both lists. This prevents old wave objects from surviving when the game restarts.

WrapTransform

WrapTransform() implements classic Asteroids screen wrapping for the player ship. If the ship crosses the right side, it appears on the left; if it crosses the top, it appears at the bottom.

OnGUI

OnGUI() draws the prototype HUD: title, score, lives, wave, controls, shield text, and the game-over restart prompt. It is not the final UI system, but it is perfect for quickly proving the game loop.

Chapter 4: Helper behaviours

The first pass keeps two helper classes in the same file. They are small movement behaviours that let rocks and bullets update themselves while the main manager handles game rules.

AsteroidsRock.Initialize

Initialize() receives the rock size, radius, velocity, spin, and arena dimensions. Those values are private to each generated rock, so every asteroid can drift and rotate differently.

AsteroidsRock.Update

Update() moves the rock by its velocity, rotates it by its spin value, and calls Wrap(). This gives each asteroid motion without a Rigidbody or physics simulation.

AsteroidsRock.Wrap

Wrap() gives rocks the same edge-wrapping behaviour as the ship. Rocks that leave one side of the arena re-enter from the opposite side.

AsteroidsBullet.Initialize

Initialize() stores bullet velocity, expiry time, and arena dimensions. The expiry time is calculated from Time.time plus the bullet lifetime, so bullets clean themselves up after a short flight.

AsteroidsBullet.Update

Update() moves the bullet, wraps it around the arena, and destroys the bullet when its lifetime expires. The manager later removes the null reference from its bullet list.

AsteroidsBullet.Wrap

Wrap() mirrors the wrapping logic used by the ship and rocks. Bullets can cross the screen edge, which keeps the prototype close to the classic Asteroids feel.

Chapter 5: Gameplay behaviour in the first pass

The first playable version is small, but it already has a complete arcade loop: the ship turns and drifts, bullets inherit direction and momentum, rocks wrap around the arena, impacts split asteroids, lives can be lost, and new waves begin when the screen is clear.

How bullets know which direction to fire

Bullets use the ship's current local up direction. In Unity, a Transform has local direction vectors such as up, right, and forward. Because the ship mesh is drawn pointing up in its own local space, rotating the ship also rotates ship.up. When FireBullet() runs, the bullet is launched along that current facing direction. 

 </>  C#
bullet.Initialize(
    (Vector2)ship.up * bulletSpeed + shipVelocity,
    bulletLifetime,
    arenaHalfWidth,
    arenaHalfHeight
);

The bullet is also spawned slightly ahead of the ship center so it appears to leave from the nose instead of from the middle of the ship. 

 </>  C#
bulletObject.transform.position = ship.position + ship.up * 0.68f;

Whether bullets travel in a straight line

Once fired, a bullet travels in a straight path. The bullet stores one velocity vector during Initialize(), then adds that velocity to its position every frame. There is no steering, gravity, acceleration, or curve on the bullet after it is created. 

 </>  C#
transform.position += (Vector3)(velocity * Time.deltaTime);

The path is still affected by the ship's movement at the instant of firing. The velocity formula adds shipVelocity, so a shot fired while drifting carries some of the ship's momentum. It is still a straight path, just not always exactly the same as the ship's nose angle if the ship is sliding sideways.

How far bullets go before despawning

Bullets do not despawn by measuring distance. They despawn by time. The public setting bulletLifetime starts at 1.25f, and the bullet records its expiry time when it is initialized. 

 </>  C#
public float bulletSpeed = 13f;
public float bulletLifetime = 1.25f;

expiresAt = Time.time + lifetime;

Every frame, the bullet checks whether the current game time has reached that expiry time. If so, it destroys itself. 

 </>  C#
if (Time.time >= expiresAt)
{
    Destroy(gameObject);
}

With the starting values, a bullet travels about 13 * 1.25 = 16.25 Unity units before timing out, plus or minus the inherited ship velocity. Because bullets wrap at the arena edges while alive, that travel can cross from one side of the arena to the other before the bullet disappears.

Screen wrapping

The ship, rocks, and bullets all use arena wrapping. When an object moves past one edge, its position is moved to the opposite edge. That means the arena behaves like a classic Asteroids screen rather than like a physical box with walls. 

 </>  C#
if (p.x > arenaHalfWidth) p.x = -arenaHalfWidth;
if (p.x < -arenaHalfWidth) p.x = arenaHalfWidth;
if (p.y > arenaHalfHeight) p.y = -arenaHalfHeight;
if (p.y < -arenaHalfHeight) p.y = arenaHalfHeight;

Collision checks

This first pass does not use Unity physics collisions. Instead, it uses simple distance checks. A bullet hits a rock when the distance between their positions is less than the rock radius plus a small bullet radius. The player is hit when the distance between ship and rock is less than the rock radius plus shipRadius. 

 </>  C#
float hitDistance = rock.radius + 0.1f;
if (Vector2.Distance(bullet.transform.position, rock.transform.position) <= hitDistance)
{
    DestroyBullet(bullet);
    BreakRock(rock);
}

Rock splitting and scoring

Rocks have three sizes. Large and medium rocks split into two smaller rocks when hit. Small rocks disappear. The score reward increases as rocks get smaller, which gives the classic arcade rhythm of breaking big hazards into faster cleanup targets. 

 </>  C#
score += rockSize == 3 ? 50 : rockSize == 2 ? 100 : 200;

if (rockSize > 1)
{
    SpawnRock(position + Random.insideUnitCircle * 0.25f, rockSize - 1, splitVelocity);
}

Respawn shields, lives, and game over

When the player is hit, LoseLife() subtracts one life. If lives remain, RespawnShip() puts the ship back at the center and enables temporary invulnerability. If no lives remain, the ship is hidden and the HUD shows a game-over prompt. 

 </>  C#
invulnerableUntil = Time.time + invulnerableSeconds;

if (Time.time < invulnerableUntil) return;

Waves and restart flow

The game starts wave one from ResetGame(). When the rock list is empty, Update() calls SpawnWave(wave + 1). Each new wave adds one more starting rock than the previous wave. After game over, pressing Space or Enter calls ResetGame() and starts the loop again.

Chapter 6: What this first pass proves

This prototype shows that a small Unity game can be made mostly from code: geometry, colors, movement, collisions, waves, UI, and restart behaviour all appear at runtime. The next interesting steps are better asteroid spawning, particle bursts, audio, smoother UI, enemy ships, pickups, and a more deliberate arena rule set.

Controls

  • WASD or arrow keys move and turn the ship.
  • Space or mouse button fires.
  • Space or Enter restarts after game over.

Verification checklist

  • The arena frame fills the Game view without cropping.
  • The cyan ship starts in the center with shields online.
  • Procedural rocks drift and wrap around the edges.
  • Bullets split large and medium rocks into smaller rocks.
  • The console is clean during the smoke test.
