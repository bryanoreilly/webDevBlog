Devlog 001: Getting the Tools

In this chapter, we install the basic tools needed to build this website: Node.js, Visual Studio Code, Git, and GitHub.

Install Node.js if you dont have it

Node.js lets us run JavaScript tools from the terminal.

https://nodejs.org/en/download

Install Visual Studio Code (or the IDE of your choice)

VS Code is the code editor we will use for this project.

https://code.visualstudio.com/

Install Git

Git tracks the history of our project.

https://git-scm.com/install/

Devlog 002: Setting up the project in Git

In this chapter, we create the project folder, add our first files, initialize Git, and push the project to GitHub.

Step 1: Create the project folder

 </>  Powershell
mkdir classic-browser-games
cd classic-browser-games

Create the files in the new folder.

Create:

classic-browser-games/
|-- index.html
|-- devlog.html
|-- projects.html
`-- styles.css

Step 2: Initialize Git

Inside the project folder:

 </>  Powershell
git init

This creates the hidden .git folder that tracks your history.

Verify:

 </>  Powershell
git status

You should see something like:

On branch master

No commits yet

Untracked files:
  index.html
  devlog.html
  projects.html
  styles.css

Step 3: Create a .gitignore

Create:

.gitignore

For this simple project:

 </>  gitignore
.DS_Store
Thumbs.db

You won't need much yet.

Step 4: Stage files

 </>  Powershell
git add .

Check:

 </>  Powershell
git status

You should see:

Changes to be committed:
  new file: index.html
  new file: devlog.html
  new file: projects.html
  new file: styles.css

Step 5: First commit

 </>  Powershell
git commit -m "Initial website structure"

This creates your first snapshot.

Step 6: Create GitHub repository

Go to:

GitHub New Repository

Repository name:

classic-browser-games

I'd leave:

Public
README unchecked
.gitignore unchecked
License unchecked

Since you already have local files and dont want an initial merge conflict.

Create repository.

Step 7: Connect local repo to GitHub

GitHub will show commands similar to:

 </>  Powershell
git remote add origin https://github.com/YOUR_USERNAME/classic-browser-games.git
git branch -M main
git push -u origin main

Run them.

Step 8: Verify

Check:

 </>  Powershell
git remote -v

Should show:

origin  https://github.com/yourusername/classic-browser-games.git

Daily workflow

After that, your workflow becomes:

 </>  Powershell
git status
git add .
git commit -m "Add homepage navigation"
git push

or

 </>  Powershell
git add .
git commit -m "Create first devlog entry"
git push

Devlog 003: Creating the devlog workflow

In this chapter, we set up the rule for the rest of the project: as the site is built, each meaningful lesson or change should become a new devlog chapter that another person could follow later.

Step 1: Decide what the devlog is for

The devlog is not just a change list. It should explain the project like a guided build. Each chapter should show the goal, the files changed, the code or commands used, and how to check that the step worked.

Step 2: Use a repeatable chapter template

Each new chapter should follow this shape:

<section id="devlog-004">
    <h2>Devlog 004: Chapter title</h2>

    <p>Short summary of what this chapter builds or explains.</p>

    <h3 id="step-id">Step 1: First action</h3>
    <p>Explain why this step matters.</p>

    <pre><code>Commands or code go here</code></pre>

    <h3 id="verify-step">Step 2: Verify the result</h3>
    <p>Explain what the reader should see when it works.</p>
</section>

Step 3: Make Codex part of the workflow

When Codex explains a build step, the explanation should also be turned into a devlog chapter. The chapter should be added to devlog.html, and the Chapters list on the right should be updated with links to the new section and its steps.

Step 4: Check the chapter before committing

Before pushing a chapter to GitHub, check:

  • The chapter has a unique section id like devlog-004.
  • Every linked heading has a matching id.
  • Commands are inside pre and code tags.
  • The chapter includes a way to verify the work.
  • The table of contents links to the chapter.

Step 5: Publish the devlog update

After the chapter looks right, save the project history and push it:

 </>  Powershell
git status
git add .
git commit -m "Add devlog workflow"
git push
